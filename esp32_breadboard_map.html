Water flow sensor hall-effect pulse type — rows 60–63

RowConnection
60PWRFlow Sensor VCC (Red wire) → LEFT RED RAIL (5V)
61GNDFlow Sensor GND (Black wire) → LEFT BLUE RAIL
62SIGFlow Sensor SIGNAL (Yellow wire) → ESP32 D27 (Row 06 Left) + 10kΩ Pull-up Leg 1
633V310kΩ Pull-up Leg 2 → RIGHT RED RAIL (3.3V)
Why the pull-up goes to 3.3V, not 5V: the flow sensor's signal pulse swings up to whatever voltage powers it. Pulling it up to the 5V rail would feed a 5V pulse into an ESP32 GPIO, which is not 5V-tolerant. Pulling up to 3.3V instead keeps the pulse at a safe logic level while the sensor itself still runs on 5V.

Firmware — pulse counting

#define FLOW_PIN 27
volatile unsigned long pulseCount = 0;
unsigned long lastCalc = 0;
float flowRate = 0;  // litres per minute

void IRAM_ATTR countPulse() {
  pulseCount++;
}

void setup() {
  Serial.begin(115200);
  pinMode(FLOW_PIN, INPUT);
  attachInterrupt(digitalPinToInterrupt(FLOW_PIN), countPulse, FALLING);
}

void loop() {
  if (millis() - lastCalc >= 1000) {
    noInterrupts();
    unsigned long pulses = pulseCount;
    pulseCount = 0;
    interrupts();

    // Calibration factor varies by sensor model — see note below
    flowRate = pulses / 7.5;  // pulses/sec ÷ K-factor = L/min

    Serial.print("Flow rate: ");
    Serial.print(flowRate);
    Serial.println(" L/min");

    lastCalc = millis();
  }
}
Calibration factor (7.5) is a placeholder — it's the common default for YF-S201-style sensors, but varies by model and pipe diameter. Check the sensor body for a printed model number to confirm the right value for yours.

Design notes

pH and EC dividers are fully separate — no resistor or row is shared between them (rows 31–35 vs 37–41).
Soil GND is the only ground in this design that doesn't touch the blue rail directly — it's switched through the transistor so GPIO25 can power-cycle the sensor and reduce probe corrosion.
Set the LM2596 to exactly 5.00V (measured on LEFT RED RAIL vs LEFT BLUE RAIL) before connecting the ESP32 or any sensor.
